# AI-Assisted Development Process

## Phase 0 — Project intake and requirements confirmation
- Read the complete documentation pack.
- Inspect the repository if one exists.
- Summarize verified current state and unresolved decisions.
- Confirm facility type, deployment, stack, institution tenancy, authority model, and initial scope.
- No code changes.

## Phase 1 — Architecture approval
- Confirm stack and deployment.
- Produce module boundary diagram.
- Produce approved domain model and ERD.
- Define API boundaries and security model.
- Define workflow engine behavior and authority matrix.
- Obtain user approval before implementation.

## Phase 2 — Foundation
- Repository and environment setup.
- Authentication and user management.
- Institution and organization configuration.
- Role and permission enforcement.
- Automated tests and seed data.

## Phase 3 — Document control core
- Document types and categories.
- Registry and numbering.
- Version and file storage.
- Document lifecycle.
- Audit events.

## Phase 4 — Workflow engine
- Workflow templates and versions.
- Sequential and parallel stages as approved.
- Task assignment and decision records.
- Return/revision, delegation, separation of duties.
- Final approval and separate release.

## Phase 5 — Distribution
- Distribution targets.
- Exact-version distribution.
- Acknowledgment tracking.
- Training evidence where approved.

## Phase 6 — Migration
- Batch upload.
- Metadata mapping.
- Duplicate/conflict detection.
- Verification queue.
- Reconciliation report.

## Phase 7 — Extended controls
- External references.
- Operational records and retention.
- Reports, notifications, backup monitoring.

## Phase 8 — Verification and deployment
- Functional, security, workflow, migration, backup/restore, and usability testing.
- User acceptance testing.
- Data migration rehearsal.
- Deployment and administrator documentation.
- Staff training and controlled go-live.

## Change control

Every material change must have:
- change request and reason;
- affected requirements/modules;
- impact analysis;
- approval where required;
- implementation and test evidence;
- updated documentation.

Do not silently alter approved requirements.
