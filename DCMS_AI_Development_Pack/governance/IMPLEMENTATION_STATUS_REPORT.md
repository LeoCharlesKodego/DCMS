## ONP guideline comparison

| Topic | Guideline / approved rule | Current implementation and difference |
|---|---|---|
| Coding format | Guideline section 6 structure, as resolved in D-019: service, section, document type, sequence; unit component for unit-level documents. Use official list, block conflicting entries, keep Master Code Register distinct from Document Control Register. | `DocumentCodeNumberingService`, `OnpCodeListSeeder`, `DocumentCodeComponent`, `MasterCodeRegisterEntry`, `DocumentRegistryController` implement component-based codes, optional unit component, sequence allocation, conflict filtering, and separate master-code entries. `base_code` is globally unique. There is no direct test for exact string formatting, component hierarchy, concurrency, or official conflicted list fixtures (**no test**). Actual `ONP` codes are not in the fictional demo; its prefix is `DEMO`. The source's 24-hour return/suggest-alternative process and high-risk code approval are not implemented. |
